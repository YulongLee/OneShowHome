# 安全、隐私与陪伴产品边界

## 1. 默认原则

- 本地优先；
- 最少收集；
- 明确同意；
- 用户可查看、导出和删除；
- AI 失败不影响本地核心体验；
- 不使用情感压力驱动留存。

## 2. 数据分类

| 级别 | 示例 | 处理要求 |
|---|---|---|
| 公开 | 应用版本、公开素材 ID | 可进入普通日志 |
| 内部 | Buddy 状态、非敏感设置 | 仅本地保存，日志最小化 |
| 私密 | 聊天、记忆、日记 | 默认不上传、不进入诊断日志 |
| 秘密 | API Key、令牌、签名凭证 | 仅安全存储，禁止进入 SQLite、源码和日志 |

## 3. 密钥管理

- 开发、测试和生产密钥分离；
- 用户 API Key 使用 macOS Keychain 或经过评审的安全存储；
- 不把密钥放入前端包、Git、`.env.example` 示例值、截图或错误信息；
- 密钥输入框默认遮挡，只显示末尾少量字符；
- 提供验证、替换和删除功能；
- 删除本地数据时询问是否同时删除 Provider 密钥；
- CI 和签名凭证使用 GitHub Environments/Secrets，限制分支和人员权限。

## 4. AI 数据传输

启用 AI 前必须显示：

- 使用的 Provider；
- 将发送哪些数据；
- 数据为什么需要发送；
- Provider 的隐私政策入口；
- 如何关闭 AI 和删除本地记录。

默认只发送完成当前请求所需的最小上下文。不要上传整个数据库或全部历史记录。

## 5. 记忆边界

不得自动保存：

- 密码、验证码、API Key；
- 银行账户、银行卡和支付凭证；
- 身份证件号码；
- 精确住址；
- 医疗诊断和高度敏感健康信息；
- 用户明确要求不要记住的内容。

用户必须能够查看记忆来源并单条删除。错误记忆应允许纠正，而不是静默覆盖。

## 6. 陪伴安全

Buddy：

- 不声称自己具有人类意识或现实身体；
- 不要求用户保守秘密；
- 不鼓励用户远离现实关系；
- 不因用户离开而责备、威胁、生病或死亡；
- 不把连续签到或付费与 Buddy 安危绑定；
- 不自称医生、心理咨询师、律师或财务顾问；
- 面对自伤或紧急风险内容时，鼓励联系现实中的可信任人员和当地紧急资源。

人格可以温暖、有情绪和生活感，但不能通过欺骗制造依赖。

## 7. 桌面权限边界

MVP 不读取：

- 屏幕内容；
- 键盘输入；
- 剪贴板；
- 浏览器历史；
- 其他应用窗口；
- 用户文件；
- 麦克风和摄像头。

未来若增加任何系统权限，必须单独编写产品理由、最小权限方案和退出机制。

## 8. 日志与诊断

- 发布版日志不记录完整聊天、Prompt、记忆或日记；
- 对用户内容使用事件 ID，不使用正文；
- 网络错误移除请求头、Key 和响应中的敏感字段；
- 崩溃上报默认关闭，开启前取得明确同意；
- 用户提交诊断包前可以看到其包含内容。

## 9. 数据生命周期

- 创建：仅在完成功能所需时生成；
- 使用：限制在当前用例；
- 保存：本地 SQLite 或安全存储；
- 导出：使用可读格式，不包含密钥；
- 删除：提供应用内入口，删除后回到首次启动状态；
- 卸载：文档说明 macOS 可能保留应用数据，并提供手动清理方式。

## 10. 发布前安全检查

- 仓库和构建产物秘密扫描；
- Tauri capabilities 最小权限审查；
- CSP 和外部域名审查；
- SQLite 迁移和参数绑定检查；
- API Key 存储与日志检查；
- AI 数据告知与同意流程检查；
- 数据导出和删除实测；
- 签名、公证和更新包完整性检查。
