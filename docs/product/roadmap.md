# OneShow Home 产品路线图

路线图使用“阶段门”管理，不以堆积功能作为进度。只有当前阶段达到退出条件，下一阶段才进入正式开发。

## Phase 0：技术可行性

### 目标

证明 macOS 桌面小屋可以稳定实现，并确定发布渠道。

### 交付物

- 双窗口 Tauri 原型；
- 透明小屋窗口；
- 多桌面空间和全屏行为测试记录；
- 点击、拖动、焦点和鼠标穿透验证；
- `.app` 构建结果；
- 窗口实现决策记录。

### 退出条件

- 核心窗口行为在真实 Mac 上可接受；
- 不存在阻断正常桌面操作的问题；
- 明确采用直接分发或调整透明窗口方案；
- 技术风险和已知限制被记录。

## Phase 1：陪伴感垂直切片

### 目标

用户可以创建 Buddy，并在第二次启动时感受到它仍然存在。

### 交付物

- 首次启动；
- 预设 Buddy；
- Living Room；
- 桌面小屋；
- 状态和昼夜系统；
- 本地持久化；
- 设置与数据清除。

### 退出条件

- `mvp-spec.md` 的 Phase 1 验收全部通过；
- 至少 5 名目标用户完成首次体验；
- 没有严重遮挡、误触、数据丢失或无法退出问题；
- 至少 3 名测试用户愿意第二天再次打开。

## Phase 2：关系连续性

### 目标

验证聊天和记忆是否增强陪伴，而不只是增加 AI 功能。

### 交付物

- 用户自备 API Key；
- 文本聊天；
- 基础记忆；
- 记忆查看和删除；
- 网络异常与隐私提示；
- AI 行为评测集。

### 退出条件

- 密钥与隐私安全审查通过；
- Buddy 人格与关键事实保持稳定；
- AI 故障不影响本地产品；
- 测试用户能感知“它记得我”，且没有明显错误记忆造成的伤害。

## Phase 3：回访与发布

### 目标

形成可交付给外部测试用户的安装版本，并验证七日回访。

### 交付物

- 日记和 Schedule；
- 三个扩展房间的最小内容；
- 开机启动；
- 自动更新策略；
- Developer ID 签名、公证和安装包；
- 隐私说明、反馈入口和发布检查表。

### 退出条件

- 生产安装包在干净 Mac 上通过安装和升级测试；
- 崩溃、CPU、内存和数据库迁移达到发布基线；
- 内测用户完成七日体验；
- 产品团队基于回访和访谈决定继续、调整或停止。

## Phase 4 以后：仅作为方向，不承诺开发

候选方向：

- 更丰富的家庭空间和装饰；
- 更细腻的 Buddy 表达与动画；
- 可选云备份；
- 多设备连续性；
- Town、World 和 Social。

任何社交或经济系统必须在本地陪伴核心得到验证后重新立项，不直接继承为既定需求。

## 版本决策机制

每个阶段结束时回答：

1. 核心假设是否得到证据支持？
2. 用户回来是因为 Buddy 的持续存在，还是只因新鲜感？
3. 哪些功能被实际使用，哪些只是展示？
4. 是否出现打扰、依赖、错误记忆或隐私担忧？
5. 下一阶段最小的可证伪实验是什么？

答案记录在 `docs/research/` 或对应版本复盘中，再更新路线图。
